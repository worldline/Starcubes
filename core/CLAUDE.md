# `core` — file notes

File-by-file notes for `core`, split out of the root `CLAUDE.md` so they
load only when work touches this directory. The project-wide rules — git
workflow, code conventions and the verification checklist — stay in the
root [`CLAUDE.md`](../CLAUDE.md); read that one too.

| File | Purpose |
|------|---------|
| `core/source.py` | `_bounded_source_engine(dsn, dialect, timeout_ms)` — a separate cached source pool whose statements cannot outlive the run budget; per dialect because there is no portable spelling (Postgres libpq startup option, Oracle `call_timeout` on the connect event, everything else logs that it is unbounded). Reached via `source_engine(statement_timeout_ms=)`. `Source` (incl. `retention_floor`; `dedupe_from` deliberately **not** here — a forever session loads its `Source` once, so `import_fact` reads that column fresh) / `Dimension` / `FactColumn` / `FactIndex` dataclasses + `Source.load` + `_get_cached_engine` + `init_oracle_client` + `watermark_fact_sql()` (fact-side watermark expression, falls back to `partition_column`) + `source_now_sql()` (the source's current time as naive **UTC**, per dialect, for the window's second upper-bound term — deliberately not the session clock). Splits `dim_fact_to_table()` (regular) from `auto_dim_fact_to_table()` (auto-dims, resolved in the parent ETL process). See [`docs/etl-engine.md`](../docs/etl-engine.md). |
| `core/schema.py` | `create_fact`, `create_indices`, `drop_indices`, `import_dimensions`, `read_dimensions`, `ensure_starcubes_meta(engine, force=)`. `validate_schema_name` + `ensure_schema` — the schema name goes unquoted into ~70 f-string SQL sites, so it is constrained to `^[a-z_][a-z0-9_]{0,62}$` rather than quoted (see [`docs/star-schema.md`](../docs/star-schema.md)); `ensure_schema` is called by `create_fact`, `create_dim_tables` and `import_dimensions` alike. Partition lifecycle: `list_fact_partitions`, `create_future_partitions` (append-only, manual), `ensure_partitions_for` (gap-filling, called every `import_fact` run), `vacuum_analyze_fact`. See [`docs/star-schema.md`](../docs/star-schema.md). |
| `core/etl.py` | `import_fact` — the three-stage pipeline; calls `ensure_partitions_for` before starting workers. `_resume_state` returns `(last_end_time, extract_from, existing_pks)`; `_overlap_pks` loads the PK set for the late-arrival overlap. The window's upper bound is `max(max_wm − watermark_lag_s, src_now − wallclock_lag_s)`, clamped up to the HWM so it can never rewind. `backfill=True` re-loads a closed window without moving the HWM. `_load_auto_dim_maps` + `_resolve_auto_dim_chunk` for parent-process auto-dim discovery. `_RunBudget` enforces `datasource.max_run_s` (raises `EtlAborted`; checked between chunks and inside `_raise_if_failed`, so both bounded queue helpers honour it) — never for a backfill, a `--start/--end` window or the initial load (`_fact_has_rows`). `_dim_refresh_due` gates `import_dimensions` on `datasource.dim_refresh_interval_s` (U4, default 0 = every run); `_source_min_watermark` + `datasource.initial_window_s` walk a catching-up load forward in bounded steps (N17 — the cap measures from the HWM, not from `extract_from`, or the late-arrival overlap eats it). `EtlAborted` for user-initiated kills; `EtlStageFailed` (+ `_put_with_abort`/`_join_with_abort`/`_raise_if_failed`) for a dead transform/load worker. Throughput metrics: `_snapshot_stats`/`_build_stats_payload` read the shared `mp.Array` into the `stats` jsonb shape (now including live `queues`/`workers`); `_rate`/`_fmt_rate` compute/format rows-per-second; `_bound_log_size` truncates the process's own log file in place. Uses `logging.getLogger(__name__)`, never `print()`. Maintenance: `truncate_last_partition`, `truncate_partition`, `drop_partition`, `delete_fact_from`, `clear_etl_history`, `set_highwatermark`, `rewind_highwatermark`. All four delete paths take the datasource advisory lock and bump the cache epoch; `delete_fact_from` is the *repair* gesture (rewinds the HWM, arms `datasource.dedupe_from` when the watermark and partition clocks differ), the partition ones are *disposal* (raise `datasource.retention_floor`, never touch the HWM — and only when the partition removed was the oldest). `run_preflight` runs at the top of `import_fact`'s `try:`, before `import_dimensions`; its report is merged into `etl_run.stats.preflight`. See [`docs/etl-engine.md`](../docs/etl-engine.md). |
| `core/preflight.py` | Pre-load checks + the datasource advisory lock. `run_preflight(source, meta_engine, dest_engine, source_engine=, repair=)` returns `{checks:[{code,level,message,detail}], repairs, blocked, ran_at}` — never raises for a *finding*; `blocking_message` turns the blocks into one sentence. Eight checks: `schema_objects` (U2, creates missing tables when `repair=True`), `meta_migrations` (N16), `indices` (U10, report only, time-aware via `STARCUBES_INDEX_WARN_ROWS`/`_HOURS`), `source_projection` (U5b — a *rejected* query blocks, an *unreachable* source only warns; they raise identically, so the connection is opened before the query runs), `watermark_tip` (U1 detection, warn only) `data_staleness` (U9/N12 — `src_now - max_wm` from the newest run against `datasource.max_data_lag_s`; a *negative* lag is reported as the watermark column not holding UTC, never as a small lag), `warehouse_drift` (U5a — reads `sync_schema`'s dry-run diff; blocks on a missing column or an unsafe type, warns on a safe widening or an orphan; the execute half stays unreachable) and `alarm_windows` (alarm windows reaching below the retention floor, which are not evaluated at all). Also `relation_exists` (shared with `etl.py`'s partition gestures) and `datasource_lock`/`acquire_datasource_lock`/`release_datasource_lock` + `DatasourceLocked` — `pg_try_advisory_lock` on a **dedicated NullPool connection**, because a session lock on a pooled one is silently lost to fork-safety, `pool_recycle` and `pre_ping`. Called from `import_fact`; the GUI runs it as a dry run (`repair=False`) via `etl/preflight/`. See [`docs/etl-automation.md`](../docs/etl-automation.md). |
| `core/housekeeping.py` | The periodic work that does not belong inside a load: `run_housekeeping(source, meta_engine, dest_engine, analyze=, trigger=)` → report dict, also INSERTed into `starcubes_meta.housekeeping_run`; `housekeeping_due(meta_engine, ds_id)` reads `datasource.housekeeping_interval_s` **fresh** (a forever session holds one `Source` for life). Retention (U3b — `datasource.retention_periods`, at most `STARCUBES_MAX_RETENTION_DROPS` partitions per run, and it does **not** take the datasource lock itself because `drop_partition` already does on its own connection; clears the plot cache as well as bumping the epoch), targeted `ANALYZE` + `brin_summarize_new_values` (U6), dim fill vs. the 32767 `smallserial` ceiling measured as `max(index)` (N13), partition sizes (N14). Two non-obvious rules, both learned from real data: ANALYZE targets are the newest partitions with `pg_relation_size > 0`, never the newest partition (`forward=1` runway) and never the calendar's current one (a stalled source leaves its rows months back); and the emptiness test must be **heap** size, because `pg_total_relation_size` counts index pages and so is non-zero on every partition once `create_indices` has run. **Takes no advisory lock on purpose** — everything in it is safe alongside a running load; retention (U3b) will be the first thing here that is not. See [`docs/etl-automation.md`](../docs/etl-automation.md). |
| `core/pipeline_alarm.py` | The second alarm kind: conditions over ETL state rather than fact rows. `CONDITIONS` maps five codes (`data_stale`, `run_failed`, `no_recent_run`, `preflight_warn`, `dim_full_pct`) to a measuring function, a **label with its unit** and a title. Each answers with a *number*, which is why `cond_op`/`threshold` and `core.alarm.episode_step` are reused rather than reimplemented; `None` means "not answerable yet" and must never close a standing episode. The label goes into the transition's `measure` key — that is what let `sources/alarm_notify.py` stay untouched. Reads `starcubes_meta` **only** (no `Source.load`, no source connection), which is what lets an evaluator outside the ETL judge a datasource whose source DB is down. `pipeline_eval_lock` — non-blocking `pg_try_advisory_lock` so the three evaluators (ETL loop, request path, `pipeline_watch`) cooperate instead of racing on `ux_alarm_firing_open`. Episodes carry the **wall clock**, not the fact clock. See [`docs/alarm.md`](../docs/alarm.md). |
| `core/query.py` | `timeseries_multibar` — multibar JSON producer. Bars ordered ascending by dim count. `split_grouped_col`/`resolve_group_set`/`slugify_group_set`/`grouped_token`/`grouped_label` own the `<col>:grouped:<slug>` token; `build_group_by_indices` resolves group names for grouped drill-down. `build_filter_tree` (flat rows → nested tree) + `validate_filter_tree`/`check_filter_col` are the shared filter validation — chart endpoints, the alarm CRUD and the evaluator all use them, so error messages must not drift. See [`docs/chart-rendering.md`](../docs/chart-rendering.md) for ladder-plot specifics. |
| `core/alarm.py` | Alarm evaluation (Django-free). `_window_below_floor` refuses to evaluate a window reaching under `retention_floor` — a truncated window makes `count(*) <` report an outage retention itself caused, while `>` only misses breaches. `episode_step` is the episode machine on its own — open/extend/close plus the `eval_end` cursor, ignorant of *why* anything breached, which is what lets `core/pipeline_alarm.py` reuse it verbatim; `stamp_transitions` adds the alarm's identity and channels (**never** an alarm column named `kind` — the transitions already use that key for opened/closed). `run_alarm_cycle(kinds=)` selects the rule kinds; `kinds=("pipeline",)` touches nothing but `starcubes_meta`. `fact_max_time` is called **once per datasource** by `run_alarm_cycle` and handed to every `evaluate_alarm` on it (`fact_max=_UNSET` sentinel, since `None` already means "empty fact"); both fact-side queries carry `STARCUBES_ALARM_TIMEOUT_MS`. `run_alarm_cycle(meta, dsn, datasource_id=, source=)` loads the enabled alarms (optionally for one datasource, optionally reusing a `Source` the caller already holds); `evaluate_alarm` evaluates the one trailing window `[hwm − window_s, hwm)` at the fact clock (`fact_max_time`), skips itself when the HWM did not move, and stamps every `alarm_firing` episode transition with that HWM; `check_no_grouped_filters` enforces the grouped-token ban on **filter columns** at save time *and* in the evaluator (a grouped `group_by` is never stored and never blocks); `measure_value_expr` owns the `count(*)` special case. Context display/compare helpers: `resolve_context_labels` (stored ids → dimension names, one query per dim table for a whole list, display-only) and `normalize_context_rows` (canonical form behind the duplicate hint). **Driven by `etl_run` after every load — there is no forever loop.** `evaluate_alarm` also returns every open/close **transition** in `counts["transitions"]` (built in the same transaction that wrote the episode row, stamped with the alarm's identity + channel config + per-alarm PagerDuty `severity`) — the Django-side dispatcher `sources/alarm_notify.py` resolves addresses (`auth_user` is Django-managed, never read here) and sends; see [`docs/alarm.md`](../docs/alarm.md). |
| `core/audit.py` | `_clamp_to_floor` raises every window's start to `source.retention_floor` (below it the fact table is empty *on purpose*, so an unclamped comparison reports 100% loss); a window entirely below the floor is refused. `audit_window` — per-bucket source-vs-fact row-count reconciliation; `audit_ids` — PK set difference naming the exact missing/surplus/duplicate rows; `audit_id_details` — targeted second pass giving each named id its own watermark-column value, the `etl_run` that should have caught it, and `last_end_time − that value` as the lower bound on the needed lag (both operands source-clock, so no skew); `_fetch_id_array` — the streaming id reader (see the memory note); `gap_span` folds the gap buckets into one backfill window. No Django imports. See [`docs/etl-audit.md`](../docs/etl-audit.md). |
| `core/cache.py` | Server-side `plot_json` cache helpers. `make_cache_key`, `is_cacheable`, `get_cached_plot`, `put_cached_plot`, `bump_cache_epoch`, `clear_cache`. No Django imports. |
| `core/utils.py` | `_parse_dt`, `_pid_alive`, `tail_file`, `format_pks` (applies `datasource.pk_format` to a list of raw PKs — shared by the chart drill-down and the Audit tab's id lists). No Django imports. |
| `core/config.py` | Global config resolver (Django-free): env var first, DB row in `starcubes_meta.app_config` (migration 0031, one KV table, key = env-var name) else None. `effective()` returns the 17 transport/SSO keys plus derived on/off booleans; `state()` is the uncached env+DB view the Transports page renders; 30 s-TTL snapshot cache + `invalidate()` on the GUI write path; DB errors never raise (WARNING + last good snapshot). Consumers: `sources/alarm_notify.py`, the Transports page, the SSO boot override (`starcubes/oidc.py:apply_db_overrides`) — this is how spawned `etl_run`/`alarm_run` see GUI-edited config. No Django imports. See [`docs/deployment-config.md`](../docs/deployment-config.md). |
| `core/adhoc.py` | Query console backend: `validate_sql` (single-statement SELECT/WITH lexer), `run_query` (read-only txn + server-side cursor + `application_name` tag), `cancel_query` (`pg_stat_activity` → `pg_cancel_backend`), `history_list` / `history_list_user` / `history_delete` / `history_delete_user`. No Django imports. See [`docs/deployment-config.md`](../docs/deployment-config.md). |
| `core/profile.py` | Source profiles: `load_profile`/`parse_profile_text` (YAML → `ExampleProfile`), `dump_profile` (meta rows → YAML, **never emits `source_dsn`**), `iter_profiles` (catalogue over `profiles/user/` then `profiles/examples/`, user wins), `save_profile`/`delete_profile`, `validate_profile_name` (the filesystem boundary). No Django imports. See [`docs/source-profiles.md`](../docs/source-profiles.md). |
