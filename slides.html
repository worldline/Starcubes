storage

2 bytes per dim. Not 20.

Dim values get a smallserial primary key. Every fact row stores a 2-byte foreign key — not the source's text or 20-byte UUID. The whole point of the compact star.

// trade-off: 32 767 values max per dim. high-cardinality keys belong elsewhere.

★starcubes
throughput

Extract. Transform. Load. In parallel.

01 / extract

Stream in chunks.

pd.read_sql against the source, paged by HWM window. Runs in the main process.

02 / transform

Map text → smallint.

N child workers do vector Series.replace + CSV serialisation. Auto-dims resolved in the parent.

03 / load

COPY FROM a pipe.

Single load worker, psycopg raw connection. Orders of magnitude faster than INSERT.

observed in examples 20 000 – 30 000 rows / second · sustained, end to end

Imported from a source-side table. The classic dim case — country, peer, customer.

inline

CSV in metadata.

Fixed value set lives in inline_values. ISO 4217 currency codes ship this way.

auto

★starcubes
cache

Calendar-aligned. Shared across users.

The client fetches in UTC calendar windows — hour, day, ISO-week, month. So when two users open the same dashboard, their HTTP requests collide on the same cache key.

The server stashes frozen count(*) responses below the HWM. Mutating endpoints bump a cache_epoch column — the key changes, old entries die.

// natural-window blocks, per bin interval
interval   historic   trailing
1s         hour       10 min
60s        day        4 hours
3600s      iso-week   1 day
86400s     month      iso-week

// cache hit condition
measure == "count(*)"
to      <= now − interval
to      <= last successful HWM
