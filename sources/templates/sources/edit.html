Python format string for PK display in chart drill-down. Use {0} as placeholder. Example: <a href="https://portal.example.com/txn/{0:012d}">{0:012d}</a>
Seconds the incremental load window reaches back past the high watermark, so transactions that become visible out of watermark order are still picked up. Duplicates are filtered by primary key, so a fact column with role=pk is required. 0 disables it. Use the Audit tab to measure the real skew before choosing a value.
Seconds the load window's upper bound stays below max(watermark), so a row that becomes visible a little late is still ahead of the window when it is read. Unlike the overlap above, nothing is re-fetched and no PK check runs — the window just advances more slowly. Only works while the source keeps producing: if traffic stops, this term freezes.
Absolute deadline in source wall-clock seconds: every row gets this long to become visible. The window's upper bound is the later of the two lags, so this one keeps the window moving when traffic pauses and the watermark lag freezes. Must be greater than the watermark lag. 0 disables the term entirely — that is not the same as a zero-length deadline. Measure it with the Audit tab's “Details” button on missing IDs. Reads LOCALTIMESTAMP on the source connection, so that session's timezone must match the one the watermark column is written in — a mismatch shifts this term by the whole UTC offset and makes it win every run.
How far the newest row in the source may lag the source's own clock before the preflight calls the source stopped. This is the only way a total standstill can be seen at all: it freezes the high watermark, so alarms cannot fire by construction and the ETL just logs rows=0. Both operands come from the source, so the figure carries no clock skew. 0 = unset, which is the honest setting for anything that does not produce continuously — a batch source running twice a day would otherwise raise a false alarm every night. Deliberately one absolute number and not a time-of-day profile; that road ends in holidays, timezones and maintenance windows.
Wall-clock budget for one ETL run. Past it the run is aborted and recorded as failed, and the same value bounds every query it sends to the source — a source that accepts the connection and then never answers otherwise blocks the extract indefinitely. Never applied to a backfill, an explicit Start/End window, or the very first load, all of which are legitimately long. 0 = unset; set it from observed run durations rather than guessing. Note it is a circuit breaker, not a repair: the next window is wider, not smaller, so pair it with Limit if runs are genuinely too big.
Deletes data, irreversibly. Keep this many partition periods; the housekeeping drops older partitions, records how far back the data still goes, and clears the plot cache. Fact partitions are UNLOGGED and nothing backs them up. At most a couple of partitions go per housekeeping run, so a mistyped value walks visibly through the log over hours instead of clearing the table in one pass — but it still walks. 0 = keep everything, which is the default. Note that alarm windows reaching below the kept range stop being evaluated: a truncated window would make a “too little data” rule fire on data you disposed of on purpose.
Width of each load window while the datasource is still catching up. With an empty fact table the first window is otherwise “everything the source has”, which on a large source is one run of hours or days during which the forever loop evaluates no alarms and runs no housekeeping. Setting this walks the load forward in steps and gives the loop its turn in between. It applies to every step of the catch-up, not only the first run; a datasource that has caught up never reaches it. 0 = one unbounded window (the default).
Seconds between dimension imports. At a 60-second forever interval the default re-reads every dimension lookup table sixty times an hour to find values that arrive maybe weekly. Throttling costs freshness, which is why it is off by default: a new value in a regular dimension shows as __unknown__ until the next refresh. Auto-dimensions are unaffected — they are resolved while extracting. 0 = every run; the Import Dimensions button always forces one.
Seconds between automatic housekeeping runs, checked by the forever loop after each load: targeted ANALYZE of the partitions being written, BRIN range summarisation, dimension fill levels and partition sizes. Defaults to 6 hours and is deliberately on — the load is COPY-only, so autovacuum's thresholds are effectively never reached, statistics on the newest partition go stale and BRIN ranges are never summarised, which silently stops the index covering the newest data. 0 disables the automatic run; the ETL Commands tab and manage.py etl_housekeeping still work by hand.
Fact-side SQL reproducing the watermark column, used to find already-loaded rows in the overlap window and by the Audit tab. Leave blank to use the partition column. Example: create_time + total * interval '1 millisecond'
