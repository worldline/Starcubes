📊 Pre-aggregation{% include "sources/_help_link.html" with slug="rollup" %}

A rollup is a column set aggregated at bucket granularity. A chart query is served from it when its breakdown and every column its filter reads are inside that set; anything else falls back to fact — slower, never wrong. Percentiles can never be served: they do not sum.

🕑 Recent runs

Every rollup_advise, rollup_build and rollup_verify, whether started here or from a shell.

{# ── Advise ─────────────────────────────────────────────────────── #}
📏 Measure

Which columns a rollup can afford is not derivable from the schema — on real data one column of a few hundred values can cost more than all the others together. This measures instead of guessing: one exact pass over a window of fact, after which every number below is computed from that. It writes nothing. Run create_indices first if the indices are missing, or every measurement scans the whole partition and the speed-up factors come out optimistic.

3600 unless there is a reason not to — see Config
24 = one day at hourly buckets
Suggests the widest set reaching it
Only when this window is not representative — on a datasource already carrying its real volume the measurement is the answer
{# ── Config ─────────────────────────────────────────────────────── #}
⚙ Column set

Coarsening is cheap, refining is not. Removing a column re-groups the small rollup table; adding one has to read fact again, and below the retention floor fact no longer has the rows. Start wide and narrow later. Changing anything here is safe at any moment: the stored rows stop matching the configuration and every chart quietly goes back to fact until a build re-establishes them.

Must divide every chart interval it should serve: 3600 covers hour and day bins, 86400 only day bins. A day bin is a UTC day — with hourly buckets, moving to local day boundaries later stays a query change; with 86400 it becomes a rebuild.
A measure changes the row width, never the row count — cheap. Adding one still needs a rebuild.
Serves a query whose breakdown and every filter column are in this set
One single-column rollup each — for a column too expensive for the core set whose unfiltered breakdown should still be fast
🗑 Drop rollup tables

Drops every rollup table of this datasource and forgets its state. Above the retention floor this is reversible — a rollup is a cache and a build reads fact again. Below it, fact no longer holds those rows, so the aggregates are the only copy there is; that span is refused unless it is confirmed explicitly.

{# ── Build ──────────────────────────────────────────────────────── #}
▶ Build now

Advance every rollup up to the finality horizon — the same work the ETL hook does after each load. A bucket is only rolled up once it is old enough that no late row can still land in it.

⏮ Backfill history

Works backwards from the newest built bucket, so the windows people actually look at become fast first and a half-finished backfill is already usable. Interruptible: every batch has committed.

Blank = the oldest row in fact
168 = one week of hourly buckets
Build a piece now, continue later
🔄 Rebuild

Discards what exists and builds it again from fact — what a changed column set needs, since the information a new column wants is not in the old rows. Refused for any span below the retention floor unless forced: a rebuild reads fact, and there fact is empty.

✅ Verify

Runs a matrix of chart queries twice — once against fact, once against the rollup the read path picks — and compares the payloads cell by cell. A case the rollup cannot serve counts as skipped, not failed: a skip is the read path correctly falling back to fact.

Correctness does not depend on the window, but every case runs the fact query too. 0 = the whole built range
