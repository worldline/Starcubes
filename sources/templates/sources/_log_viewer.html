{% load static %} {% comment %} The one log viewer: lines from starcubes_meta.log_line and runs from the view starcubes_meta.run, behind one filter panel (sources/log_views.py). Included by sources/logs.html (all datasources, filters in the URL) and by source.html's ETL Log sub-tab (fixed_datasource set, no URL state). Behaviour in sources/static/sources/log_viewer.js; the includer constructs it: new StarcubesLogViewer(document.getElementById(viewer_id)) Parameters: - viewer_id id of the root element - kinds, levels the vocabularies (log_views.RUN_KINDS / core.log_ship.LEVELS) - hosts host names for the host filter (the JS shortens the labels) - datasources [{id, name}] for the datasource filter (omit with fixed_datasource) - fixed_datasource a datasource id the viewer is pinned to; adds .lv-fixed, which drops the Datasource column from both views - url_state truthy: mirror the filters into the page URL Layout: filter panel (two rows) / view header / pane / status line. Both views are newest first. The Lines column header lives inside the pane as a sticky row, so it scrolls sideways with the rows on a narrow screen. The kind options in kind-add are the vocabulary the JS reads once; it rebuilds the list from it. {% endcomment %}
